# 重建算法选择

在「免费计算 → 参数确认 → 重建算法」中选择：

| 选项 | 算法 | 适用素材 |
| --- | --- | --- |
| 通用重建（gsplat / 3DGS） | 当前 gsplat 三维高斯训练器 | 常规物体、室内外场景 |
| 薄物体、植株重建（2DGS） | 本地已有 2DGS 的原生 surfel 训练器 | 叶片、植株等薄表面 |

两者均可选择完整场景，或通过 SAM3 提示词保留目标。提示词中应包含需要保留的标定物，例如 `potted plant; blue cube`。成功发布后均进入既有 Edit 标定界面。

这里的尺寸标定是用已知长度恢复整个模型的真实尺度：在模型中测出方块某条边的长度，再以「该边实际长度（米）÷ 模型测量长度」为倍率，让植株、方块和其他内容一起等比例缩放。例如实际边长 20 mm、模型测得 0.25，整体倍率就是 `0.02 / 0.25 = 0.08`。在官方 Editor 的 Measure 距离框输入 `0.02` 完成缩放，导出后回传发布；平台表单计算倍率并保存记录。发布后重新测量用于检查结果。

算法与质量独立，页面默认选择通用重建与标准质量（30,000 次）。草稿明确标为快速预览，为 1,200 次迭代；标准和高精度均为 30,000 次迭代，分辨率等参数按既有质量配置生效。界面显示所选质量的实际迭代数；选择 2DGS 不会自行降低迭代数。该适用场景说明不是本项目已完成两种算法精度对照的声明。

## 接口与持久化

`POST /api/v1/compute/reconstruct` 增加 `algorithm`，只接受 `gsplat` 或 `2dgs`，省略时兼容旧请求，使用 `gsplat`。算法写入既有 Job 的 JSON 参数，随每个 Celery 阶段读取；`GET /api/v1/jobs/{id}` 返回已保存的算法，刷新页面后也能看到实际算法。无需数据库迁移。

算法参与任务幂等和训练/检查点标识；不同算法不会复用同一个活跃任务或训练检查点。2DGS 源文件变化也会使训练缓存失效。环境缺失时明确报错，不会静默切换为 gsplat。能力接口的 `tools.2dgs` 表示部署路径已配置，CUDA 扩展是否可运行由训练子进程实际校验。

## 2DGS 运行环境

GPU worker 可设置 `GS_2DGS_REPO` 和 `GS_2DGS_PYTHON`。当前主机复用 `/data/fj/F2DMAS/2d-gaussian-splatting-main` 和其中的 `venv/bin/python`，无需修改该仓库。依赖使用该环境已有的 torch、diff_surfel_rasterization、simple_knn、numpy、Pillow、plyfile。

适配器对 RGB 和 SAM3 掩膜做相同的去畸变、下采样和主点居中变换，再交给 2DGS 的 PINHOLE 相机读取器。提示词模式会过滤初始点云，并启用该仓库已有的前景 RGB、掩膜和背景透明度损失；沿用其 SSIM、法线与深度正则设置，不宣称重新实现论文全部配置。当前本地默认 `lambda_normal=0.05`、`lambda_dist=0.0`。

原生双尺度 surfel PLY 保存在 `checkpoints/2dgs/point_cloud/iteration_N/point_cloud.ply`，检查点原子保存并可续训。进度直接来自训练迭代回调，取消仍由既有子进程组管理。

## 编辑器兼容

既有 SOG/Editor 使用三轴高斯，因此发布时保留位置、颜色、旋转与两个切向尺度，附加较小切向尺度的 1/1000 作为有限法向厚度。原生 2DGS PLY 保留不变。训练使用原生 2DGS，发布显示采用薄椭球近似；共享编辑器不是原生 2DGS 光栅器。世界坐标未改动，后续两点测量与等比例缩放沿用现有流程。
