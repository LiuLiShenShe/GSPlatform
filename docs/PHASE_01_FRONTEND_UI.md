## 实现细节

### 推荐模块边界

- `app/`：Provider、Router、错误边界。
- `layouts/`：平台布局和 Viewer 全屏布局。
- `pages/`：路由页面，仅编排业务模块。
- `features/`：scene、work、compute、upload、viewer-shell。
- `components/`：无业务绑定的复用组件。
- `services/`：Axios 客户端、DTO 适配、错误类型。
- `stores/`：Zustand 状态；不存储可由 URL 或服务端直接得到的数据。
- `fixtures/`：仅开发/测试使用，打包生产前可检验地禁用。

### 布局建议

桌面内容区按 `repeat(5, minmax(0, 1fr))` 建立 5 列。设置明确断点，在较窄视口降为 3、2、1 列；每个断点都写测试。Poster 使用固定纵横比容器避免布局抖动。

### 数据状态

本阶段允许 fixture 驱动 UI 验证，但必须满足：

- 文件放在 `src/fixtures/`。
- 页面显示开发环境标识或由测试环境注入。
- 生产构建不会将 fixture 当作 API 成功响应。
- Report 不得把 fixture 数据列为后端完成证据。

### 可访问性

- Sidebar 当前项使用语义化导航状态。
- 表单元素均有 label 与错误关联。
- Drawer、Modal 和 Popover 能正确管理焦点。
- 仅图标按钮必须提供 `aria-label` 或等价可访问名称。
